# OPC UA Connect 2.5.0

This release makes entity names follow the PLC structure, turns the side panel into one entity table and makes new nodes use subscriptions by default.

## Entity names from the PLC structure

- A field whose name repeats across struct instances (for example `xEnable` in several pumps) now gets its parent struct instance in the name, so the entities can be told apart.
- New per-endpoint option **Include PLC path in entity names** (default off; options flow and a switch in the panel). When on, a brand-new node is named after its full symbolic path and the panel can group by path.
- Generated names now read like the PLC symbol, for example `SP.xError` or `astAlarms[3].xActive`. Names saved by earlier versions are migrated once and only on an exact match; names you typed yourself stay untouched.
- Path grouping keeps small sibling groups, keeps a failed save's error message and the panel search also matches the path.

## New nodes use subscriptions

A newly discovered node is saved with update mode `subscription`, so push updates apply as soon as the endpoint's **Auto-Subscription** switch is on. Nodes that are already known keep their update mode.

## Side panel (1.12.0)

- All entities of an endpoint in one table with fixed, resizable columns (widths are remembered in the browser); groups are folding heading rows and the header row stays visible while scrolling.
- German panel texts, following the Home Assistant language.
- Endpoint switches look like Home Assistant switches; help texts are info tooltips on the labels.
- A click on a row (or Enter) opens the editor; the NodeId is shown below the name field.

## Updating from 2.4.0

Update the integration and restart Home Assistant. Refresh the browser if needed: the integration should display **2.5.0** and the panel **1.12.0**.

Existing entity IDs do not change. Generated names are migrated once as described above. Existing nodes keep polling unless you switch them to subscriptions.
