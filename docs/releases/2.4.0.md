# OPC UA Connect 2.4.0

This release adds numeric conversions and live entity customization, and fixes persistent duplicate-name warnings for renamed array fields.

## Numeric conversions

- Configure a multiplier or linear scale for numeric sensors and numbers directly in the panel.
- Convert values on read and apply the inverse conversion to native number commands. For example, a factor of `0.1` displays PLC value `253` as `25.3`, and writing `23.5` sends `235` to the PLC.
- Map two PLC endpoints to two Home Assistant endpoints, including descending scales.
- Configure number limits and step in Home Assistant units when a conversion is enabled.
- Apply decimal-place rounding after conversion, including converted integer nodes.
- Keep coordinator and restored values raw to prevent double conversion.

Conversions default to None. Integer writes round to the nearest integer, with exact ties rounded to even, and validate the OPC UA type and safe integer range. Linear scales extrapolate outside their endpoints; they do not clamp values. Subscription deadband and the low-level raw write service continue to use PLC values. Units remain separate display metadata.

## Customize entities without reloading the endpoint

Changes to Always available, boolean inversion, decimal places, conversions, number/text limits, units and device classes now update existing entities immediately after Save. The OPC UA session and subscriptions remain connected.

Always available can also be changed while the connection is disabled if verified node metadata is already loaded or cached. Enabling it saves the metadata needed for offline startup; it does not invent missing values or discover unknown nodes.

Category, associated NodeId, connection settings, subscription mode and deadband changes still reload the endpoint. The panel reports a reload only when required.

## Array-field naming fixes

- The Rename array fields action now persists the generated name in node settings as well as the entity registry.
- On rediscovery, reconcile names generated by the previous implementation when the registry name exactly matches the expected array-field name.
- Preserve deliberately different custom names and existing entity IDs.
- Prevent duplicate-name warnings caused by those already-renamed fields.

## Updating from 2.3.0

Update the integration and restart Home Assistant. Refresh the browser if needed: the integration should display **2.4.0** and the panel **1.9.1**.

No endpoint recreation or domain migration is required. Existing values are not scaled unless you explicitly configure a conversion. Review number limits and step when enabling or removing a conversion. Subscription opt-in behavior is unchanged.
